# Youth UX and release playtesting — Hamza and team

## First-time comprehension
- [ ] Without coaching, explain why oxygen, power, water and spare parts matter.
- [ ] Explain how crew selection changes risk.
- [ ] Identify when the game moves from sunlight to lunar night.
- [ ] Explain what a risky choice could cost before selecting it.
- [ ] Finish the debrief and explain why outcome and decision-quality score differ.

## Gameplay passes
1. Run **Doctor + Engineer**, choosing the safe option until the final turn.
2. Run **Field Specialist + Scientist**, choosing a risk whenever available.
3. Run **Doctor + Scientist**, investing early and playing safe later.
4. Run **Engineer + Field Specialist**, trying to drain power to zero.
5. Replay any crew combination to see whether randomness changes outcomes without changing ex-ante score for the same choice situation.

Record for each attempt: crew pair, decisions, turns survived, mission outcome, score, most confusing text, any rule exploit, and suggested change.

## Required engineering checks
- [ ] All resource values stay within 0–10.
- [ ] A turn cannot be submitted twice.
- [ ] After mission over no more choices can be submitted.
- [ ] A low critical resource is visible without relying only on color.
- [ ] Gameplay works on phone and desktop, including keyboard navigation.
- [ ] The review distinguishes game mechanisms from observed NASA data.
- [ ] A scientist/engineer verifies any NASA gap IDs or new scientific statements.
- [ ] The actual official challenge selection and submission requirements are checked.

## Release blockers
No approval/production deployment until: tests pass; mobile/desktop gameplay is manually checked; provisional mechanic discrepancies are reviewed with Emir; and scientific-source claims are checked.
